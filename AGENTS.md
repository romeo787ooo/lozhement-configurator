# Инструкции для Codex

## Архитектура и карта файлов

- Статическое приложение на обычном JavaScript, без сборщика и npm-проекта. `index.html` — конструктор, разметка и основные стили; `projects.html` — локальный кабинет. Дополнительные стили — `css/`.
- Скрипты подключены через обычные `<script>` и используют общую область видимости. Порядок в HTML важен; `js/main.js` запускает конструктор последним.
- `js/core/state.js` — состояние `S` и черновик; `js/app.js` — результат анализа `A`, общий `refresh()` и авторасстановка `relayout()`.
- `js/core/projects.js`, `js/ui/project-session.js`, `js/ui/projects-page.js` — хранение, сохранение и кабинет проектов. Данные находятся в `localStorage`, серверных аккаунтов нет.
- `js/data/` — каталог, шаблоны, демопроекты и подготовленные сетки кейсов `case-mesh-*.js`.
- `js/core/geometry.js`, `orientation.js`, `packing.js`, `arrange.js`, `analysis.js`, `pricing.js` — геометрия, ориентация, упаковка, размещение, проверки и цена.
- `js/core/tiers.js` и `stepped.js` — съёмные ярусы и ступенчатые карманы; одноимённые файлы в `js/ui/` — их интерфейс.
- `js/ui/` — интерфейс: `items-tree.js` и `compact-tree.js` — дерево; `sketch-editor.js` — редактор контура; `layout.js` — панели и полный экран; `tools.js` — команды и меню.
- `js/view/plan-2d.js` — план 2D; `view-3d.js` — Babylon.js (WebGPU с резервным WebGL); `case-model.js` и `foam-fit.js` — корпус и посадка ложемента.
- `js/view/interaction-scene.js` и `scale-scene.js` — режимы «Человек и кейс», переноска и сравнение размеров. Эти демонстрации не должны менять проект.
- `js/export/` — DXF, SVG, данные заказа и ZIP, включая ярусы.
- `js/core/item-models.js` и `js/ui/import-model.js` — локальный импорт OBJ/STL, проекции и встроенные сетки изделий; проверка `tools/check_item_models.py`.
- `carvekit_server.py` — отдельный локальный сервис выделения по фото. `tools/` — проверки и подготовка моделей; `assets/` — ресурсы. Конвертацию см. в `tools/README.md`, модель человека — в `assets/human/interaction/README.md`.

## Правила изменений

- Решай текущую задачу минимальным связным изменением. Не меняй несвязанные модули, оформление, зависимости или архитектуру «заодно». Не продолжай отложенные задачи без запроса.
- Перед изменением прочитай затронутый код и его вызовы. Исторические разделы README могут быть устаревшими: сверяй их с текущими файлами.
- Сохраняй существующий стиль JS и UTF-8, включая русские строки. Не переводи проект на модули/фреймворк и не добавляй сборку без отдельной задачи. Избегай конфликтов глобальных имён.
- Размещай расчёты в `core`, интерфейс в `ui`, отрисовку в `view`, экспорт в `export`. Переиспользуй существующие функции вместо копирования логики.
- Сохраняй совместимость проектов и черновиков. Новым полям нужны безопасные значения по умолчанию; не очищай пользовательский `localStorage` для исправления ошибки.
- Размеры проекта — в миллиметрах. Учитывай преобразования координат и единиц при импорте моделей; не меняй пропорции контура или производственные размеры ради картинки.
- После изменения состояния используй подходящий существующий путь обновления. `relayout()` меняет размещение: не вызывай его там, где требуется только перерисовка или `refresh()`.
- Не редактируй большие сгенерированные сетки вручную. Меняй генератор и пересобирай только нужный ресурс; сохраняй сведения об источниках и лицензиях.
- Новые команды должны согласовываться с существующим интерфейсом; кнопкам-иконкам нужны понятные подсказки и доступные названия.

## Запуск и проверка

- Из корня: `python -m http.server 5500 --bind 127.0.0.1`, затем `http://127.0.0.1:5500/`. Если сервер уже работает, используй его. Через `file://` не проверяй.
- При необходимости используй `.venv/Scripts/python.exe` вместо `python`. CDN-зависимостям нужен интернет; не подменяй их версии без причины.
- Для задач CarveKit: зависимости в `requirements-carvekit.txt`; запуск `python -m uvicorn carvekit_server:app --host 127.0.0.1 --port 7000`. Для обычного UI сервис не нужен.
- Подбирай проверки по изменению: `tools/check_projects.py`, `check_tiers.py`, `check_stepped.py`, `check_tree_workflow.py`, `check_compact_tree.py`, `check_sketch_expansion.py`, `check_foam_fit.py`, `check_lid_motion.py`, `check_interaction.py`. Перед запуском прочитай требования конкретного скрипта; браузерные проверки используют Python Playwright и локальный сайт.
- Проверяй пользовательский сценарий и ошибки консоли в отдельном браузерном контексте, не на сохранённых проектах пользователя. Для UI осматривай результат; для 3D — несколько ракурсов. Числовая проверка сама по себе не доказывает визуальную корректность.
- Изменения геометрии проверяй в затронутых потребителях: анализ, 2D, 3D, сохранение, экспорт. Для регрессии добавляй содержательную проверку причины ошибки, а не копию реализации.
- Перед завершением проверь diff и `git diff --check`. Для правки только документации достаточно сверить содержание, пути и diff. В отчёте указывай выполненные проверки и ограничения; не заявляй успех непроведённой проверки.

## Git

- Начинай с `git status` и изучения существующих изменений. Не откатывай, не удаляй и не включай в свою работу чужие или несвязанные правки.
- Не используй массовое форматирование, `git reset --hard`, `git clean` или принудительный push для наведения порядка.
- Коммит, push, merge и деплой выполняй только по запросу пользователя. Перед ними проверь целевую ветку, remote и состав diff; добавляй в индекс конкретные относящиеся к задаче файлы.
- Не коммить окружения, кэши, временные скриншоты, исходные CAD-архивы или секреты. Не добавляй тяжёлые ресурсы без необходимости для задачи.
